# 图片与写作规范

站点的每张图都应该有唯一归属。乱放会带来两个问题：图片在线上打不开、仓库越来越胖。

## 一、三种图，三个位置

| 用途 | 存放位置 | 文章里怎么写 |
| --- | --- | --- |
| 文章配图（截图、电路图、实物照） | `public/notes/<slug>/image/` | `![](/notes/<slug>/image/xxx.webp)` |
| 独立照片 / 相册（不属于某篇文章） | `public/photos/2026-10/` | `![](/photos/2026-10/xxx.webp)` |
| 站点素材（头像、favicon） | `public/` 根目录 | `/avatar.webp` |
| 分享封面（微信/抖音卡片） | 构建时自动生成到 `dist/og/` | 不用管 |
| 原始大图（不发布、只本地留档） | `raw/`（已 gitignore） | 不引用 |

`<slug>` 就是文章的网址尾段，例如 `git-github-desktop`。

**为什么不能放 `src/`？** `src/` 是源码目录，里面的图片只有被代码 `import` 才会进打包，Markdown 里的路径引用不到它。只有 `public/` 下的文件会原样出现在线上。

## 二、命名规则

- 小写字母 + 中划线，语义化：`cf-01-workers-pages.webp`、`uart-timing.webp`
- 同一篇文章里加序号前缀，保证排序稳定：`cf-01`、`cf-02`……
- **不要用** `1.png`、`微信图片_20260712.png`、`4c868fec-...png` 这类名字，三个月后没人认得出

## 三、尺寸与体积

- 宽 1400–1500px 就够（正文最宽 860px，2 倍屏也清晰）
- 格式统一 `.webp`，质量 82
- 单张控制在 200KB 以内；超过就说明该裁或该压
- 手机拍的照片先裁掉多余的背景，截图只保留有用区域

## 四、截图必须先检查隐私

发布前逐张看一眼，以下内容要裁掉或打码：

- 邮箱、手机号、真实姓名
- 云服务账号 ID、子域名（如 `xxx.workers.dev`）
- 二维码、支付信息、聊天记录里的头像

## 五、一条命令搞定转换

照片先丢进 `raw/`，再执行：

```bash
# 单张，进某篇文章
npm run photo -- raw/1.png --slug git-github-desktop

# 整个目录，依次命名 cc-01、cc-02……
npm run photo -- raw/ --slug lecture-07 --name cc

# 独立照片
npm run photo -- raw/海边.jpg --photos
```

脚本会自动：转 webp、缩到 1500 宽、放到正确目录、打印可以直接粘贴的 Markdown。

可选参数：`--width 1200`、`--quality 80`、`--name 前缀`。

## 六、图注怎么写

```markdown
![](/notes/git-github-desktop/image/cf-01-workers-pages.webp)
```

方括号里留空 → 图上不显示说明。
方括号里写一句中文 → 图片下方显示为图注：

```markdown
![Workers & Pages 页面：右上角蓝色按钮就是「创建应用程序」](/notes/git-github-desktop/image/cf-01-workers-pages.webp)
```

（方括号里若是文件名，比如 `Snipaste_2026-07-05.png`，会被自动判定为噪音，不显示图注。）

## 七、发布前自检

- [ ] 图片都在 `public/notes/<slug>/image/` 或 `public/photos/` 下
- [ ] 引用路径以 `/notes/` 或 `/photos/` 开头
- [ ] 没有残留 `./xxx.assets/` 这类相对路径
- [ ] 每张图都能在本地 `npm run dev` 里正常显示
- [ ] 截图里没有隐私信息
