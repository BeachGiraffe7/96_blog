# 米醋电子工作室-TI M0系列 第二讲 串口 & 超时中断 & DMA+Ringbuffer

不管你是用 MSPM0、STM32 还是别的芯片，串口都是你和芯片交流的“眼睛和嘴巴”。我们用最直观的“寄快递”比喻，带你轻松搞懂串口。

## 什么是“串口”？（单车道 vs 高速公路）

计算机里传输数据有两种方式：

- **并口（并行通信）**：像一条 8 车道的高速公路，8 个比特（bit）的数据同时出发，并排冲向终点。速度快，但极其占用引脚（需要 8 根线）。
- **串口（串行通信）**：像一条**单车道**的乡间小路，数据必须排成一队，**一个比特接一个比特地**往前走。

**为什么单片机都爱用串口？** 因为省引脚。芯片上一根引脚就是真金白银，串口只需要极少的引脚就能实现通信。

## 串口的三根核心线（缺一不可）

要让两个设备（比如你的 MSPM0 和电脑）通过串口说话，最少需要连接 **3 根线**：

| **管脚名称**      | **作用**           | **接线规则（核心！）**            |
| ----------------- | ------------------ | --------------------------------- |
| **TX** (Transmit) | 发送数据端         | 必须交叉接对方的 **RX**           |
| **RX** (Receive)  | 接收数据端         | 必须交叉接对方的 **TX**           |
| **GND** (Ground)  | 地线（信号参考点） | 必须**共地**（双方 GND 连在一起） |

> ⚠️ **容易踩的两个大坑：**
>
> 1. **忘记交叉**：很多人理所当然地把 TX 接 TX，RX 接 RX，结果就是两个人都用嘴对着嘴（TX对TX），耳朵对着耳朵（RX对RX），谁也听不见谁说话。
> 2. **忘记接 GND**：电压是相对的。如果两个设备不接 GND，它们就没有统一的“0伏”标准。单片机发出的 3.3V 高电平，在电脑看来可能是低电平，导致数据全是乱码。

## 串口通信的“接头暗号”（四大参数）

因为串口通信没有一根专门的“时钟线”来指挥大家齐步走（这叫**异步通信**），所以双方在说话前，必须提前约定好一套“暗号格式”。这就是你在 SysConfig 里经常看到的参数：

### ① 波特率 (Baud Rate) —— 说话的速度

- **含义**：每秒钟传输多少个比特（bit）。
- **常用值**：`9600` 或 `115200`。
- **规则**：双方**必须完全一致**！如果单片机用 115200 的速度语速飞快，而电脑串口助手用 9600 的速度慢吞吞地听，电脑收到的就会全是乱码。

### ② 数据位 (Data Bits) —— 包裹的体积

- **含义**：一口气传输的一帧数据里，真正有用的信息有几位。
- **常用值**：通常是 **`8` 位**（正好是 1 个字节，可以容纳一个 ASCII 字符）。

### ③ 校验位 (Parity Bit) —— 快递安检

- **含义**：用来检查数据在传输路上有没有被干扰、有没有出错。
- **常用值**：`None`（无校验，最常用）、`Odd`（奇校验）、`Even`（偶校验）。

### ④ 停止位 (Stop Bit) —— 句号

- **含义**：用来告诉对方，这一段话说完了。
- **常用值**：**`1` 位**。

## 拆解一帧串口数据（数据长什么样？）

当你用串口发送一个字符（比如字母 'A'）时，线上的电压会发生一连串的高低变化。这一串变化被称为一个**数据帧（Data Frame）**，它的标准流程就像寄快递：

1. **空闲状态**：平时没人说话时，线路上一直维持着**高电平（1）**。
2. **起始位（拉低通知）**：准备发数据时，TX 会突然把电平拉低（0）并保持一下。这就好比快递员敲门：“注意啦，我要开始送货了！”
3. **数据位（正文）**：紧接着，按顺序发出 8 个高低电平（0 或 1），代表你的数据。
4. **校验位（安检）**：可选的，用来验货。
5. **停止位（恢复）**：最后，TX 把电平**重新拉高（1）**。等于盖个戳：“本件投递完毕，恢复清静。”

前面聊到的 **MSPM0 的 4 级 FIFO**，就是用来装这些源源不断送进来的 8 位“数据包裹”的。

## 电脑和单片机通信的“翻译官”：电平转换

为什么单片机不能用一根 USB 线直接把 TX/RX 连到电脑上？

因为它们的**语言电压（电平）不同**：

- **单片机（TTL电平）**：0V 代表数字 0，3.3V（或5V）代表数字 1。
- **电脑 USB 或老式串口（RS232电平）**：用正负十几伏来代表 0 和 1。

如果直接硬连，单片机薄弱的引脚会直接被电脑的高电压烧毁。

所以，我们中间必须加一个“USB 转 TTL 模块”（常见的芯片有 CH340、CP2102 等）。现在很多开发板（包括你的 MSPM0 板子）都自带了板载调试器，它已经帮你把这个“翻译官”集成在板子上了，你只需要插上 USB 线，电脑就能识别出一个 `COM口`。

## 什么是 FIFO？

**FIFO** 是 **First-In, First-Out** 的缩写，意思是**先进先出**。

- **生活小比喻**：就像去食堂排队打饭，排在第一个人（先来）的一定最先打完饭离开（先走）。或者像一根两头通的管子，你从 A 端按顺序塞进去红、黄、蓝三个球，从 B 端出来的顺序也一定是红、黄、蓝。
- **在单片机硬件中**：它就是一个**硬件缓冲区**。比如 MSPM0 的 UART 接收数据时，数据不是直接扔给 CPU，而是先存进一个硬件 FIFO 队列里，CPU 再从 FIFO 里依次把数据读出来。

## 硬件和软件中的“另一种”机制

你印象中“另一种其他的”机制，根据不同的场景，通常指以下两种：

### 数据结构上的死对头：LIFO（后进先出 / 栈 Stack）

与 FIFO 相对的就是 **LIFO (Last-In, First-Out)**。

- **生活小比喻**：像一摞洗好的盘子，你洗好一个往上叠一个（进栈），用的时候只能从最上面拿走最后一个叠放的盘子（出栈）。
- **单片机中的应用**：单片机的 **Stack（栈）** 就是典型的 LIFO 结构。当你调用函数或者触发中断时，当前的 CPU 寄存器状态、局部变量会被“压入栈顶”（Push），保护现场；执行完后，再从栈顶“弹出”（Pop）恢复现场。

### 传统硬件通信中的对比：单寄存器模式（No FIFO）

在一些老旧或者极简的单片机里，外设是没有 FIFO 缓冲区的。

- **单寄存器模式**：移位寄存器收到一个字节，立刻覆盖到 `RXDATA` 寄存器中，并触发中断。如果 CPU 这时候在忙别的，没有在下一个字节传输完毕前把这个字节读走，数据就会被后续的数据**直接覆盖**，这叫 **Overrun（接收溢出错误）**。

## 如何结合 MSPM0 来理解 FIFO？

TI 的 **MSPM0**（无论是 M0L 还是 M0G 系列）在串口等外设里都内置了 **4级（4-element）硬件 FIFO**。

### 为什么 MSPM0 要设计 4 级 FIFO？

假设你的 MSPM0 串口波特率是 115200bps，大约每 86 微秒（$\mu s$）就会收到一个字节。

- **如果没有 FIFO**：单片机每 86$\mu s$ 就要进一次中断，CPU 频繁被打断，根本没心思干别的复杂工作，稍微卡顿一下数据就丢了。
- **有了 4 级 FIFO**：硬件可以帮你临时连存 4 个字节。通过 TI 的 **SysConfig** 图形化配置工具，设置 **FIFO 触发阈值（Trigger Level）**：
  - 例如设置成 `1/2 full`（即接收到 2 个字节时触发中断）。
  - 这样 CPU 只要去一次中断，就能一口气读走 2 块甚至更多的数据。这不仅**大幅减少了 CPU 进出中断的死区时间**，还给 CPU 争取了更长的响应容错时间。

**串口接收超时中断（RX Timeout Interrupt）**，通俗来说就是单片机的“发呆检测机制”。

它是专门用来解决一个通信难题的：“**在不知道对方要发多少个字节的情况下，如何判断对方已经把话说完了？**”

### Sysconfig中 UART FIFO 配置详情

- **`RX FIFO contains >= 1 entry` (包含至少 1 个数据)**
  - **对应数量**：1 个字节。
  - **含义**：只要架子上放了 1 个及以上的快递盒，就立刻触发中断。
- **`RX FIFO is full` (完全装满)**  
  - **对应数量**：4 个字节。  
  - **含义**：必须等 4 个格子全部塞满，才会触发中断。如果只来了 3 个，它就死等，绝不通知 CPU。  
- **`RX FIFO >= 3/4 full` (大于等于 3/4 满)**
  - **对应数量**：4 × 3/4 = **3 个字节**。
  - **含义**：当架子上堆了 3 个或 4 个快递盒时，触发中断。
- **`RX FIFO >= 1/2 full` (大于等于 1/2 满)**
  - **对应数量**：4 × 1/2 = **2 个字节**。
  - **含义**：当架子上堆了 2 个、3 个或 4 个快递盒时，触发中断。
- **`RX FIFO >= 1/4 full` (大于等于 1/4 满)**
  - **对应数量**：4 × 1/4 = **1 个字节**。
  - **含义**：当架子上堆了 1 个及以上的快递盒时，触发中断。

- **`TX FIFO <= 3/4 empty` （触发极早）**
  - **含义**：当 FIFO 里的数据减少到 $\le 3$ 个字节时（即只要空出了 1 个字节的位子）就会触发。
  - **场景**：适合每次中断只想填入 1 个字节的极精细控制，但由于触发太频繁，会增加 CPU 的中断开销。
- **`TX FIFO <= 1/2 empty` （最常用 / 默认平衡项）** 
  - **含义**：当 FIFO 里的数据减少到 $\le 2$ 个字节时（即已经空了一半或更多）触发。
  - **场景**：这是最推荐的**黄金平衡点**。它给 CPU 留出了发送另外 2 个字节的时间来响应中断，同时允许你进入中断后一口气往里面写入 2 个新字节，效率最高。
- **`TX FIFO <= 1/4 empty` （触发较晚）**
  - **含义**：当 FIFO 里只剩下 $\le 1$ 个字节时触发。
  - **场景**：留给 CPU 响应的缓冲时间比较短。如果波特率极高且 CPU 此时在处理其他耗时任务，可能会导致串口短暂“断流”。
- **`TX FIFO is empty` （完全空了再触发）**
  - **含义**：只有当 FIFO 里的 4 个字节全部发送完毕、彻底变成 0 个字节时才触发。
  - **场景**：常用于**单次数据包发送完毕的尾部处理**。比如在 485 通信中，必须确保所有数据彻底吐出去了，才能把控制引脚从“发送模式”切回“接收模式”。
- **`TX FIFO is not full` （只要不满就触发）**
  - **含义**：只要 FIFO 没装满（哪怕里面有 3 个字节，还剩 1 个空位）就会不断触发。
  - **注意**：**慎用！** 如果你使能了 TX 中断却没及时把 FIFO 填满，MCU 会陷入死循环式的“中断暴风”，导致主程序卡死。

## 🛠️ 实际开发建议

1. **常规中断 / DMA 连续发送**：直接保持图中的 **`TX FIFO <= 1/2 empty`**。每次触发中断后，在代码里往 `TXDATA` 连续写入 2 个字节，既不容易断流，也不会频繁打断 CPU。
2. **多机通信 / RS-485 切换方向**：配合使用 **`TX FIFO is empty`** 或者利用 UART 的 `EOT`（End of Transmission，传输彻底结束）中断，来精准把握切换引脚方向的时机。

> **💡 小疑问：为什么 `contains >= 1 entry` 和 `>= 1/4 full` 算出来都是 1 个字节，SysConfig 却有两个选项？**
>
> 这是因为 TI 的底层驱动库为了兼容其他更大 FIFO（比如某些大芯片有 8 级或 16 级 FIFO）的外设，在软件上保留了通用的标准写法。在 MSPM0 这款 4 级 FIFO 的芯片上，这两个选项在**硬件触发效果上完全是一模一样的**。

### 聊天小比喻：怎么判断对方“讲完了”？

想象一下，你在微信上和朋友聊天，朋友在给你讲一个八卦。他不是一口气发一大段话，而是一句一句、甚至一个词一个词地往外蹦（就像串口一个字节一个字节地发数据）：

> 朋友：“我跟你说……” （过了2秒） 朋友：“今天小明……” （过了1秒） 朋友：“去相亲了！” （过了10分钟，再没动静了）

这时候你心里一定会做出判断：**“等了10分钟都没新消息，他肯定已经说完了。”** 于是你开始根据收到的完整信息哈哈大笑或者回话。

这“等待的10分钟”**就是**超时时间；而你决定不等了、开始处理信息的这个**动作**，就是触发了**超时中断**。

### 传统方法 vs 超时中断

在处理电脑发来的“变长数据”（比如有时候发 5 个字节，有时候发 10 个字节）时，通常有两种办法：

- **方法 A（死板的方法）**：约定好每个数据包最后必须带上回车换行（`\r\n`）。单片机每次收到数据都检查是不是 `\n`，如果是，就认为说完了。
  - *缺点*：如果传输的是图片、坐标等复杂的二进制数据，里面本身就可能包含和 `\n` 一样的数据，这就会导致误判。
- **方法 B（超时中断法）**：单片机内部有一个“小沙漏”（定时器）。
  1. 只要串口收到一个字节，小沙漏就**立刻倒过来重新计时**。
  2. 如果数据源源不断地进来，沙漏就永远漏不完。
  3. 一旦对方发完了最后一个字节，停止发送了，小沙漏就会**滴答滴答漏完（到期触发）**。
  4. 硬件此时会大喊一声：“报告 CPU，已经有一段时间没有新数据进来了！”——这就触发了**超时中断**。

## 核心代码架构解析

你的系统里有两个“池子”在配合工作：

1. **池子 A（硬件池）：`uart_dma_rx_buf[256]`** 这是专门给 DMA 用的“自动化传送带”。DMA 会在这个数组里不断地从 0 写到 255，写满后自动回到 0 覆盖重写（SysConfig 里配了 Repeat 模式）。
2. **池子 B（软件池）：`uart_rx_rb` (256字节)** 这是给业务逻辑（CPU）用的。CPU 不直接去碰硬件池，而是通过 `usart_dma_rx_poll()` 函数，把池子 A 里的新数据“抄写”到池子 B 里，然后应用层通过 `usart_read()` 安全地拿走数据。

### 最精妙的逻辑：`usart_dma_rx_poll()` 是怎么工作的？

DMA 在后台默默搬砖，不会主动通知 CPU 它搬了多少。你是通过一种“游标追赶”的数学计算来提取数据的：

- **算写游标**：`remain = DL_DMA_getTransferSize(...)` 获取 DMA 还需要搬多少个字节才完成 KPI。 用总长度 `256 - remain`，就得出了当前 DMA 刚刚把数据写到了数组的哪个下标（即**写游标 `curr_write_pos`**）。
- **对比读写游标**：系统记住上一次读到了哪里（**读游标 `last_dma_read_pos`**）。只要 `curr_write_pos != last_dma_read_pos`，就说明 DMA 搬入了新数据。
- **分段抄写（解决绕回问题）**：
  - **情况 A（没绕回）**：写游标在读游标前面，直接把这一段拷贝进 RingBuffer。
  - **情况 B（写绕回了头部）**：写游标跑到了读游标的后面。此时需要分两步抄：先抄读游标到数组末尾（255）的那一段，再抄从 0 到当前写游标的这一段。

### 为什么在 `uart_task` 和 `UART_0_INST_IRQHandler` 里都要调 poll？

- **超时中断里调**：当一帧数据发完，总线空闲触发超时中断，立刻把 DMA 刚搬完的数据抄出来，保证**低延迟**。
- **`uart_task` 轮询调**：如果外部数据流非常大，连绵不断，根本没有空闲时间触发超时中断怎么办？`uart_task` 里的轮询保证了即便没有中断，只要 CPU 跑到了这个任务，也会主动去池子里把积压的新数据抄出来，保证**不溢出**。

##  DL库UART API 详解

### 1. UART 发送相关 API

#### `DL_UART_Main_isTXFIFOFull`

- **功能**：检查 UART 的硬件发送 FIFO 是否已满。
- **参数**：
  - `uart` (类型 `UART_Regs *`)：UART 外设的基地址指针。在你的代码中传入的是宏 `UART_0_INST`（指向 UART0 寄存器组）。
- **返回值**：`bool` 类型。`true` 表示 FIFO 已满，不能再塞数据了；`false` 表示还有空位。

#### `DL_UART_Main_transmitData`

- **功能**：向 UART 发送移位寄存器（或 TX FIFO）中写入 1 个字节的数据准备发送。
- **参数**：
  - `uart` (类型 `UART_Regs *`)：UART 外设基地址。
  - `data` (类型 `uint8_t`)：要发送的 8 位字节数据。

### 2. DMA 配置与控制 API

#### `DL_DMA_disableChannel`

- **功能**：强制关闭指定的 DMA 通道。配置 DMA 之前**必须**先调用此函数将其关闭，否则新配置不会生效甚至导致硬件异常。
- **参数**：
  - `dma` (类型 `DMA_Regs *`)：DMA 模块的基地址，通常直接传入宏 `DMA`。
  - `channelNum` (类型 `uint8_t`)：要操作的 DMA 通道号。代码中传入的是宏 `DMA_CH0_CHAN_ID`（通道 0）。

#### `DL_DMA_setSrcAddr` / `DL_DMA_setDestAddr`

- **功能**：分别设置 DMA 搬运数据的**源地址（从哪拿）\**和\**目的地址（放哪去）**。
- **参数**：
  - `dma` (类型 `DMA_Regs *`)：DMA 模块基地址。
  - `channelNum` (类型 `uint8_t`)：通道号。
  - `addr` (类型 `uint32_t`)：32 位的绝对内存地址。代码中源地址是串口接收寄存器 `&UART_0_INST->RXDATA`，目的地址是数组 `uart_dma_rx_buf`。

#### `DL_DMA_setTransferSize`

- **功能**：设置 DMA 的传输计数器（KPI总量），即 DMA 通道在触发完成中断（或重置指针前）需要搬运的次数。
- **参数**：
  - `dma`, `channelNum`：同上。
  - `size` (类型 `uint16_t`)：传输次数。最大值为 65535（64k）。代码中设为 256。

#### `DL_DMA_setSrcIncrement` / `DL_DMA_setDestIncrement`

- **功能**：设置每次搬运完成后，源地址和目的地址指针是否要向后移动。
- **参数**：
  - `dma`, `channelNum`：同上。
  - `increment` (枚举类型 `DL_DMA_ADDR_INCREMENT`)：
    - `DL_DMA_ADDR_UNCHANGED`：地址保持不变（代码中用于源地址，因为串口寄存器位置永远固定）。
    - `DL_DMA_ADDR_INCREMENT`：地址递增（代码中用于目的地址，因为要把数据按顺序塞进数组）。

#### `DL_DMA_enableChannel`

- **功能**：使能指定的 DMA 通道。调用后，DMA 进入“待命”状态，一有硬件触发信号（如 UART RX 中断）就开始搬运。

#### `DL_DMA_getTransferSize`

- **功能**：**这是你实现轮询逻辑的核心 API。** 它用于实时读取当前 DMA 计数器中**还剩下多少个数据没有搬**。
- **返回值**：`uint16_t`，剩余传输量。当它刚好为 0 时，如果配置了 Repeat 模式，硬件会自动将其重置为你最初设定的总数（256）。

### 3. UART 中断相关 API

#### `DL_UART_Main_getPendingInterrupt`

- **功能**：获取当前 UART 模块中**优先级最高**且**正在等待处理**的中断标志。
- **特性**：这是一个“读取并清除”（Read-to-Clear）API。当你调用它并获取到返回值的同时，硬件会自动把这个中断标志位清零，不需要你再手动调用 `ClearPendingIRQ`。
- **返回值**：一个枚举值（如 `DL_UART_MAIN_IIDX_RX_TIMEOUT_ERROR`），你可以用 `switch-case` 结构来优雅地进行分支处理。

很多初学者在用到 RingBuffer（环形缓冲区）时都会产生这个疑惑：**“既然 RingBuffer 自己就是环形的、带读写游标的，为什么我在 DMA 中断里还要自己算一遍游标和绕回？”**

答案是：**必须要算，这二者不可替代。**

因为这里其实存在**两个完全独立的“环”**。你代码里的 `usart_dma_rx_poll()` 扮演的是一座桥梁，负责把数据从“硬件环”搬运到“软件环”。

结合你贴出来的 RT-Thread `ringbuffer.c` 源码，我为你详细拆解为什么这部分计算省不掉：

### 核心原因：`rt_ringbuffer_put` 要求源数据在内存中是“连续的一块”

你看你贴出的源码中，`rt_ringbuffer_put` 函数的核心操作是什么？是**拷贝**。

```
// 截取自你发来的源码 rt_ringbuffer_put 函数
rt_memcpy(&rb->buffer_ptr[rb->write_index], ptr, length);
```

`rt_memcpy` (本质就是 C 标准库的 `memcpy`) 需要三个参数：目标地址、**源起始地址**、连续长度。这就要求你传给它的源数据 `ptr`，在物理内存上必须是**连续、没有断层**的。

### 两个“环”的根本区别

- **软件环（池子 B：`uart_rx_rb`）：** RT-Thread 的 RingBuffer 确实自带读写游标（`read_index`, `write_index`）和翻转镜像逻辑（`write_mirror`）。当你调用 `rt_ringbuffer_put` 时，如果**软件环**自身的尾部空间不够了，它会聪明地帮你把数据拆成两半，一半放尾部，一半放头部。这体现了它的“环形”特性。
- **硬件环（池子 A：`uart_dma_rx_buf`）：** DMA 硬件在死磕你的 `uart_dma_rx_buf` 数组。当 DMA 写满 256 字节时，它在硬件层面瞬间把指针“瞬移”回了数组的下标 0。**RT-Thread 的 RingBuffer 对这种硬件级别的瞬移一无所知。**

###  poll 里的分段判段

假设 DMA 一共接收了 10 个字节。但是，它写这 10 个字节的时候，恰好跨越了数组的末尾（比如从下标 250 写到了绕回后的下标 4）。

如果你不自己做逻辑判断，企图直接调用 RingBuffer：

```
// 错误做法：企图直接传给 RingBuffer
rt_ringbuffer_put(&uart_rx_rb, &uart_dma_rx_buf[250], 10);
```

这时候 `rt_memcpy` 就会从 `uart_dma_rx_buf[250]` 开始，盲目地往后连读 10 个字节。读到 255 之后，它不会聪明地回到 0，而是会**读越界（读到数组外面的未知内存引发 HardFault 或野指针错误）**！

## 什么是欧拉角

欧拉角（Euler Angles）是用来在三维空间中描述一个物体“朝向”或“旋转状态”的一种数学方法。

简单来说，任何一个三维物体的任何一种复杂的旋转姿态，都可以被分解为**绕三个互相垂直的坐标轴（$X$轴、$Y$轴、$Z$轴）的连续三次旋转**。这三个旋转的角度，就是欧拉角。

为了最直观地理解它，我们通常会引入“飞行器模型”，这在航空航天、无人机、3D游戏开发中最为常用。

### 欧拉角的三要素：偏航、俯仰、翻滚

想象一架飞机，它的机身中心有一个三维坐标系，飞机的朝向可以通过以下三个角度来完全定义：

1. **偏航角 (Yaw - $\psi$) - 绕 $Y$ 轴旋转：**
   - **动作：** 飞机的机头向左或向右转动，就像汽车在平地上转弯一样。
   - **生活类比：** 你坐在椅子上，身体不倾斜，仅仅是向左看或向右看。
2. **俯仰角 (Pitch - $\theta$) - 绕 $X$ 轴旋转：**
   - **动作：** 飞机的机头上抬或下压，准备爬升或俯冲。
   - **生活类比：** 你点头（向下看）或仰头（看天空）。
3. **翻滚角 (Roll - $\phi$) - 绕 $Z$ 轴旋转：**
   - **动作：** 飞机机头方向不变，但左机翼上抬，右机翼下降，整个飞机在空中“打滚”。
   - **生活类比：** 你的脸正视前方，但把头向左肩或右肩歪过去。

### 欧拉角的两个重要特点

- **顺序极其重要：** 欧拉角不是同时发生的，而是**按顺序**依次旋转的（例如先 Yaw，再 Pitch，最后 Roll）。旋转顺序不同（比如 $XYZ$ 顺序和 $ZYX$ 顺序），即使三个角度数值一模一样，最终物体的朝向也会完全不同。
- **万向节死锁 (Gimbal Lock)：** 这是欧拉角最著名的缺陷。当其中一个旋转角达到 $90^\circ$（比如飞机机头完全垂直指向天空）时，另外两个旋转轴会重合在一起。此时，系统会丢失一个自由度，导致无论怎么旋转，物体都只能在一个二维平面内变化，无法再进行某些方向的旋转。
